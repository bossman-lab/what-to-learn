# 缰绳时代：从拼模型到拼驾驭系统

> 系列之二。第一篇《护城河的迁徙》讲了模型层为何没有护城河；
> 本篇讲价值转移到了哪里——以及一个残酷的推论：harness 本身也在持续萎缩。

---

## 一、2026 年的共识转移

如果你在 2026 年观察 AI 圈，会发现一个用词的变化：

| 过去的说法 | 现在的说法 |
|-----------|-----------|
| "我们的模型更强" | "我们的系统更能干活" |
| 拼模型（参数、榜单） | **拼驾驭系统（harness）** |
| 关注"模型有多聪明" | 关注"任务完成率、成本、可靠性" |

行业里开始流行一个公式：

> **Agent = Model（大脑）+ Harness（缰绳）**
> **决定落地成败的，是后者，不是模型本身。**

**"缰绳"这个词选得很准**——它既描述了功能（驾驭），也暗示了关系（马是外部给定的，你只能驾驭）。

---

## 二、什么是 harness？

**定义**：包裹在模型外、让它"能做事"而不只是"能回答"的**全部软件基础设施**。

| 属于 harness | 不属于 harness |
|-------------|---------------|
| 工具调用与编排 | 模型权重 |
| 上下文工程（喂什么、什么时候喂） | 预训练 |
| 记忆与状态管理 | 注意力机制 |
| 重试 / 回退 / 路由 | 推理内核 |
| 成本与延迟控制 | — |
| 安全与隔离 | — |
| **判断层（决定下一步做什么）** | — |

**一句话**：**模型负责"智能"，harness 负责"让智能落到现实里"。**

---

## 三、为什么是"现在"？——两个条件同时成熟

### 条件 1：模型跨过了"够用"阈值

这是关键。当模型能力从 60 分到 90 分时，每一分都值钱；从 90 分到 95 分时，**用户感知不到**。

**数学表达**：

```
价值的边际回报 = (dV/dM) × (dM/dC)
                    ↑          ↑
              需求侧饱和   供给侧变贵
```

**两个递减函数相乘 → 能力投资的边际回报加速递减。**

这就是"**模型能力的边际价值递减区**"——注意不是"瓶颈期"（暗示停滞），也不是单纯的"平台期"（暗示静止），而是**价值转移**。

### 条件 2：模型持续商品化

开源（DeepSeek / Qwen / Llama）把"前沿能力"变成了免费输入。
**当模型是商品时，差异化只能在模型之外——也就是 harness。**

---

## 四、实证：2026 年两个爆款都不是赢在模型

### Jev：**harness 替换模型**

一个不聊天、不写代码、**只做判断**的模型（是/否、选择、打分）。

| 维度 | 前沿大模型 | Jev |
|------|-----------|-----|
| 响应 | 3s - 329s | **70-500ms** |
| 输入成本 | $0.20-10/百万 token | **$0.042** |
| 快 | — | **193.6 倍** |
| 便宜 | — | **444.6 倍** |

它的创始人（ChatGPT 联合发明人 Diogo Almeida）的核心追问：

> "参与共同发明 ChatGPT 之后，我一直在问：**为什么超人级别的聊天模型没有带来 AGI？**"

他的答案：

> "今天的 AI 非常擅长**协助**，但还不擅长**自动化**。"
> "为什么大模型总需要人在回路里？因为训练它的时候，**我们字面意义上就把人塞进了那个回路**。"

**Jev 击败的不是"模型能力"，是"用法"**——它证明了：**放弃通用能力、专精于一个 harness 环节（判断），就能赢。**

### Muse：**harness 包装模型**

Meta 的消费级智能体，10 天 250 万下载，登顶美区 App Store。

它爆火的三个秘密，**每一个都和模型无关**：

| 秘密 | 本质 |
|------|------|
| **门槛低** | 不需要提示词，说想干什么就行 → **产品设计** |
| **能省钱** | #Muse Money Challenge → **价值交付** |
| **够安全** | 独立云虚拟机 + 一次性卡号 + 审批 Agent → **信任工程** |

**原文的判断**：
> "Muse 爆火的秘密不是它有多聪明，是**它让用户觉得真能干活，而且出了事也无所谓**。"

### 还有一个数据佐证

> **2025 年，近 65% 的企业级 AI 项目失败，归因于上下文漂移与记忆丢失，而非模型能力不足。**

**这条最有力**：失败主因不是模型不行，是 **harness 太烂**。

## 五、Harness 的三个战场

| 战场 | 代表 | 实质 |
|------|------|------|
| **判断 / 路由层** | Jev | 用便宜快的专用判断替代昂贵通用生成 |
| **上下文工程** | MCP / A2A 协议 | 管理"喂给模型什么"——65% 失败率的来源 |
| **安全 / 信任层** | Muse | 隔离、一次性凭据、审批链 |

**注意**：三个战场里，**没有一个是"让模型更聪明"**。

---

## 六、但最残酷的推论：**harness 本身也在持续萎缩**

这是本文最重要的一节。

**不要以为"价值转移到 harness"意味着 harness 是永久的护城河。** 恰恰相反——

**harness 的历史，就是一部不断被模型吞掉的历史**：

| 曾经的 harness | 现状 |
|---------------|------|
| 链式思考提示（CoT）| ✅ **已被原生推理模型吞掉** |
| 提示词工程 | ✅ 被指令微调吞掉 |
| RAG 编排 | ⏳ 正被长上下文 + 原生检索吞掉 |
| 通用工具编排 | ⏳ 正被原生 function calling 吞掉 |

**规律**：

> **凡是"能标准化 + 能泛化"的 harness 技术，都会被下一轮模型吃掉。**
> **只有"对接到具体现实"的部分留下来。**

---

## 七、判据：harness 里什么是"接口"，什么是"编排"

由此得到一个**极硬的判断标准**（详见系列之三）：

> **问它是【规律】还是【历史】？**
>
> - **规律**（可泛化、可标准化）→ **会被吞**
> - **历史**（具体、私有、不可约、要问责）→ **会留下**

**应用到 harness 内部**：

| 会被吞（规律） | 会留下（历史） |
|---------------|---------------|
| 链式思考脚手架 | 私有数据 |
| 提示词模板 | 组织流程 |
| 通用 RAG 管线 | 责任链 / 问责 |
| 通用 agent 框架 | 领域直觉 |
| 标准化工具协议 | **不可标准化的接口** |

**推论（反直觉）**：

> **协议标准化（MCP / A2A）反而会加速模型对 harness 的吞噬**——
> 因为它们把接口变成了"通用可学"的东西。
>
> **真正抗吞噬的，是那些"不能标准化"的接口**：私有、异质、带问责。

---

## 八、Bitter Lesson 的警告

Sutton 的"苦涩教训"说：**长期看，靠算力和通用方法总能赢过人类手工设计的工程。**

**harness 本质上就是"人类手工设计的工程"。**

所以：

| 如果…… | 那么 harness 的护城河…… |
|---------|----------------------|
| 下一个能力跃迁到来 | **大部分被洗掉** |
| 能力缓步提升（当前路径）| **持续升值** |

**结论**：harness 是"**当前阶段**的护城河"，**不是"永久的"护城河**。

---

## 九、结语：该站在哪一侧

> **不站在"模型"一侧，也不站在"harness"一侧——**
> **站在"harness 里那个不可被标准化、不可被泛化、不可被委托"的部分。**

因为那部分的锚不在趋势上，在**数学与物理**上——这是系列之三要展开的内容。
