# 第二章：HLT评分——在模糊中做比较的能力

如果你只能从这本书里带走一个工具，那应该是HLT。

它是一个评分系统——不是精确的（世界上没有精确的学习价值计量器），而是在模糊中做比较的工具。

HLT分别回答三个问题：

```text
H（Half-life · 半衰期）：这个知识多久之后还有价值？
L（Leverage · 杠杆）：学会之后，你的什么能力会提升？
T（Transferability · 迁移性）：这个知识能不能迁移到别的问题上？
```

三个分数乘起来，得到一个粗略的学习价值评分：

```text
HLT = H × L × T
```

下面逐一看每个维度。然后是阈值系统、常见打分陷阱、以及如何使用。

## 2.1 H：半衰期——这个知识多久还有价值

H衡量的不是"这个知识新不新"，而是它的价值衰减速度。

一个东西可以很新，但半衰期很短——比如今天新发布的某个框架的API用法，三个月后可能就过时了。

一个东西也可以很老，但半衰期很长——比如信息论的几个基础概念，几十年了，仍然在解释新现象。

很多人会把"新"误认为"值得学"。新框架、新论文、新模型、新工具，天然带有一种吸引力。它让你觉得自己站在前沿。但前沿里有很多东西只是浪花。浪花很高，退得也快。

给你一个简单的锚点来打H分：

```text
H = 1-2：一年内明显过时。
  某个框架的特定API用法、某个热门产品的操作步骤、某个版本的配置语法。

H = 3-5：三到五年仍有价值。
  某个领域的主流方法论、一套成熟的工程实践、一类通用问题的解法。

H = 6-8：十年以上仍有价值。
  基础概念和原理、核心算法思想、普适设计原则、学科底层的逻辑结构。

H = 9-10：随时间增值。
  认知框架、思维方式、跨领域模式识别能力、元认知技能。
```

操作上，你可以用一个简单问题判断H值：

```text
如果我五年后重新遇到这个问题，今天学到的这部分还会帮我吗？
```

- 答案"基本不会，文档肯定变了" → H低
- 答案"具体工具可能变，但这个处理方式还在" → H中等
- 答案"只要人类还在处理这类问题，它就会继续有效" → H高

注意一个常见的误判：**不要用知识的"经典程度"代替"对你的H"。**

微积分是很经典，H客观来说可以到9。但如果你在未来三年完全不碰需要微积分的工作，那它对你是"低H"。——但等等，这个说法容易引发争议。准确地说，不是它的H对你降低了，而是它的L（杠杆）对你低了。H和L是独立的维度，不要混在一起打。后面我们会看到一个具体例子。

## 2.2 L：杠杆——学会后你的什么能力会提升

L衡量的不是"这个知识本身重不重要"，而是"学会它之后，你的什么会变"。

注意定义里的一个关键词：**你的**。不是你所在行业里有价值，不是抽象意义上人类知识有贡献，是**你当前和未来一段时间的实践能力**会改变。

锚点：

```text
L = 1-2：学会后几乎用不上。
  主要提供知识满足感，不改变你的实践。

L = 3-5：学会后能做一件以前做不了的事。
  一个具体任务、一个特定场景。

L = 6-8：学会后能做以前做不了的一类事。
  打开一整类问题的能力，出现的频率较高。

L = 9-10：学会后重构你对某个重要领域的认知方式。
  一次学习，长期改变你的判断、设计和行动。
```

L最常见的误判：用"知识的客观重要性"代替"对你的杠杆"。

很多东西确实重要，但对你杠杆很低。你是后端工程师，短期内完全不做图形学，一本经典图形学教材H可能很高——但它不改变你接下来三年的任何实践，L就是低。

这跟教材好不好、你有没有兴趣完全无关。L是极其自私的维度。它只关心一件事：**学完这个之后，你明天能做什么跟今天不一样的事？**

你再问一遍自己这个问题。如果答案模糊——"可能以后有用""理论上应该有用"——那L就是偏低的。不骗自己。

## 2.3 T：迁移性——能迁移到多少领域

T衡量的不是"这个知识有没有用"，而是"离开原场景后还剩下什么"。

锚点：

```text
T = 1-2：只在这个具体场景有用。
  某个工具的操作路径、特定平台的工作流。

T = 3-5：在同一大类问题中通用。
  一套特定领域的方法论、一个专业方向的实践框架。

T = 6-8：能迁移到不同领域。
  反馈回路、瓶颈分析、守恒思想、机会成本、系统思考。

T = 9-10：跨领域后反而更有价值。
  元认知技能、思维模型、压缩框架、预测能力。
```

检查T的操作问题：

```text
这个知识离开原场景后，还剩下什么？
剩下的东西能不能解释其他领域的类似问题？
我能不能用它改写一个非本领域的案例？
```

如果离开原场景后什么都不剩，T低。如果剩下一个模式、一个约束、一个trade-off、一个判断框架，T就有价值。

T容易被高估。大多数人容易把"类比"误认为"迁移"。类比只是看起来像。迁移必须能产生判断——你能用它在另一个领域做出预测或决策。高T不是漂亮的比喻，是能跨场景做判断的内在结构。

## 2.4 H×L×T：乘法公式与阈值系统

为什么用乘法不是加法？

因为一个维度低，会严重拖垮整体价值：

- H很高（经典原理），L很低（你用不上）→ 现在不该深学
- L很高（能解决问题），H很低（很快过时）→ 现查现用，不投入长期记忆
- H和L都高，T很低（只在一个专业场景有用）→ 是否深学取决于你是否长期在这个场景

乘法强迫你尊重短板。

阈值系统：

```text
HLT ≥ 300：🏆 核心杠杆
→ 值得投入深度学习。进入精通五层流水线。

HLT 150-299：✅ 高价值
→ 值得学，学到可用程度即可，不一定走完所有层级。

HLT 75-149：📊 一般
→ 快速了解，提取核心结构。不投入深度压缩。

HLT < 75：⚠️ 不值得
→ 不学比学好。最多现查现用。
```

这个阈值不是自然定律。它是一个决策工具。

真正重要的是：**你终于有了"不学"的理由。**

很多人的学习系统里没有"不学"这个动作。只有"现在学""以后学""收藏起来"。收藏夹成了一个无限延迟队列，里面装着永远不会被处理的学习债务。

HLT要做的事情，就是把这些债务清掉。拿一张纸，写下10个方向，打一轮分。低于75的全部划掉——你不需要为它们内疚。

高阶学习者真正稀缺的不是信息，是深度处理能力。HLT就是在问：这个知识配不配占用我的深度处理能力？

大多数时候，答案应该是"不配"。

这不是消极。相反，这是让少数真正重要的东西有机会被学透。
