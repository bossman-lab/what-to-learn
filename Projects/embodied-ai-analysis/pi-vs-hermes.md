# Pi vs Hermes 架构对比：能抄进工作流的东西

**日期：2026-08-10 · 目的：用 Pi 的极简哲学审视自己的 agent 架构**

---

## 一、架构对照表

| 维度 | **Pi**（earendil-works） | **Hermes**（Nous Research，你在用） |
|------|------------------------|--------------------------------------|
| 设计哲学 | "做减法"——让你自己决定需要什么 | "全功能"——什么都能干 |
| 核心工具 | **4 个**：read / write / edit / bash | 30+ 工具（browser、terminal、cron、delegate、MCP…） |
| 系统提示词 | <1000 tokens（含工具定义） | 数千 tokens + 记忆注入 + skill 加载 |
| 隐藏注入 | **零**（全透明） | 有（记忆、上下文压缩、系统 prompt 组装） |
| 模型绑定 | 不绑定，任意 provider | 多 provider + 配置化 |
| 长时任务 | 无内置（要自己搭） | **cron 系统**（你 26+ 个任务在跑） |
| 子 agent | 无内置 | **delegate_task**（背景并行） |
| MCP | 无（核心） | 有（你接了 t2-models、lantern-monitor 等） |
| 多平台 | 终端 | Telegram / Discord / CLI / 公众号 |
| 扩展机制 | extensions（可自修改 harness） | skills / plugins / scripts |
| 自我改进 | 可自修改 harness（自举） | 手动 skill 沉淀（/learn、curator） |
| 稳定性风险 | harness 极简 → 漂移面小 | harness 复杂 → 漂移面大（CLOSE-WAIT、SearXNG、Tavily 配额……都是实例） |

---

## 二、Pi 揭示的三个本质问题（值得抄进工作流的洞察）

### 1. "harness 漂移"概念——解释了你踩过的所有自动化坑

Mario 的核心痛点：**模型没变，变的是 harness，工作流就坏了。**

对照你的实际经历：

| 你踩过的坑 | 本质 |
|-----------|------|
| SearXNG 引擎被封 → 搜索超时 | 外部环境漂移，破坏工作流 |
| Tavily 配额耗尽 → web_extract 失效 | 依赖漂移 |
| 网关 CLOSE-WAIT 泄漏 → 消息发不出去 | 基础设施漂移 |
| V4 正式版发布 → 幻觉率变化 | 模型漂移 |

**可借鉴**：Pi 的解法是"让确定性部分保持确定"——工具集、prompt、注入全部固定透明。你的 Hermes 工作流无法完全照搬（你需要全功能），但可以**给关键任务建立"确定性基线"**：比如核心 cron 任务锁定模型版本（thinking: disabled）、搜索依赖双通道（SearXNG + curl 直抓）、关键数据源幂等快照（价格监控已做 ✅）。

### 2. "模型天然懂 coding harness"——少即是多的证据

Terminus 只给一个工具却常拿第一 → **堆功能不必然提升效果。**

**可借鉴**：审视你的 agent 调用链——**很多"中间层"可能是负担**。比如：
- 你的 web_search 出问题时，直接 curl 反而更可靠（已实践 ✅）
- 你的 delegate_task 有时候直接自己干更快（背景任务不可靠时）
- **原则**：复杂工具链出问题时，先想"能不能用最简路径绕过"，而不是修链条

### 3. 透明性 = 可诊断性

Pi 零隐藏注入 → 出问题一眼看穿。Hermes 有记忆压缩、系统提示词组装 → 出问题时"为什么它这么想"难排查。

**可借鉴**：你已经在做的"凭据纪律 + 版本时间纪律"就是透明性的体现。可以更进一步：**关键决策留痕**（哪个模型、哪个版本、哪个数据源、什么时候）——你的 cron 报告已经在做，保持。

## 三、能不能直接换用 Pi？（诚实评估）

| 场景 | 结论 |
|------|------|
| 你现在的 Telegram 网关 + cron 自动化 | ❌ 不能换——Hermes 的多平台 + cron 是刚需，Pi 没有 |
| 日常编码任务（改代码、跑脚本） | ✅ 可以试——Pi 极简透明，编码场景够用 |
| 复杂 agent 编排（多平台、MCP） | ❌ Pi 不适合——无 MCP 无子 agent，要自己搭 |
| 学习 agent 原理 | ✅ 强烈推荐——agent-loop.ts 一个文件就是全部精华（简书有拆解） |

**结论：不是二选一，是互补。** Hermes 当"生产调度层"（cron/多平台/自动化），Pi 当"编码工作台"（要确定性和透明时的选择）。两者都用，各取所长。

## 四、行动项（能直接做的）

1. **装 Pi 试两天**（`curl -fsSL 安装`，GitHub: earendil-works/pi）——用它在 /tmp 或临时项目里跑几个编码任务，体验"零隐藏注入"的确定性
2. **把"确定性基线"写进你的自动化原则**：核心任务锁定模型版本 + 双通道数据源 + 幂等快照（价格监控已是范式，推广到其他 cron）
3. **读 agent-loop.ts**（简书拆解文）——一个文件理解 agent 本质，比看十篇综述强
